# Нейрометр: локальная утилита (Agent)

**Нейрометр** проверяет возможности компьютера для локального ИИ, строго разделяя обнаруженное, оценённое, измеренное и неизвестное. Локальная утилита разрабатывается на **Go**; первая поддерживаемая платформа — **Windows x64**.

Проект состоит из **двух связанных репозиториев**:

- [neurometr-agent](https://github.com/Herurg123/neurometr-agent) — локальная диагностика и экспорт JSON (этот репозиторий).
- [neurometr-web](https://github.com/Herurg123/neurometr-web) — статический сайт, просмотр диагностических файлов, канонические контракты и каталог моделей.

## Текущее состояние

В основной ветке реализованы нативный сбор Windows CPU/RAM/GPU, обработка частичных ошибок и **обычный офлайн-экспорт диагностического JSON v0.1.0** с проверенным комплектным каталогом. Обязательного запуска llmfit и подключения к сети для быстрой аппаратной диагностики нет. Результат проходит JSON Schema Draft 2020-12 и семантические проверки.

**Статус веток:** в `main` подтверждены аппаратная диагностика Windows и обычный офлайн-экспорт `diagnostic.json` v0.1.0. **A3.4 находится в отдельном Draft PR:** защищённый localhost UI и локальная история реализуются и проверяются, но ещё не объединены и не опубликованы. Единого пользовательского Windows ZIP с llmfit по-прежнему нет; модели не загружаются автоматически, их работа и TPS не проверялись.

## Текущая разработка (Draft, ещё не в main)

### A3.4. Защищённый localhost UI и локальная история

- [Draft PR #7](https://github.com/Herurg123/neurometr-agent/pull/7): отдельный Go HTTP-интерфейс внутри Agent, динамический порт на `127.0.0.1`, проверка Host/Origin, защищённая cookie-сессия и CSRF для запуска проверки.
- Встроенная русскоязычная страница работает офлайн, показывает результаты и ограничения, историю, полный валидированный JSON и ручной экспорт. История хранится в локальном профиле Windows, повторно проверяется по полной JSON Schema v0.1.0. Новые отчёты используют существующий нативный `diagnostic.Generate` и закреплённый каталог `2026.11.11.2`.
- На этом этапе проходят GitHub Actions проверки, а не публичный выпуск. Реальная безопасность и работоспособность на компьютере владельца **не подтверждены**. [Подробности A3.4](docs/A3_4_LOCALHOST_HISTORY.md).

**Запуск интерфейса для облачных проверок исходников, после сборки Windows x64:** `go run ./cmd/localui -root .`. Команда предназначена для разработческого CI, **не** требует от владельца установки Go. Готовый пользовательский ZIP и удобный дистрибутив будут отдельным согласованным этапом. Без `-no-browser` приложение пытается открыть стандартный браузер автоматически.

## Проверка исходников

Сборка и тесты выполняются преимущественно в **GitHub Actions**. Для разработчика с установленным Go на Windows x64 доступен тестовый CLI в текущем `main`:

~~~powershell
go run ./cmd/contractcheck -root .
go run ./cmd/catalogcheck -root .
go run ./cmd/diagnose -root . -output diagnostic.json
~~~

Это **не** инструкция владельцу устанавливать Go. Для конечного пользователя предусмотрен отдельный готовый ZIP, его выпуск пока не состоялся. Диагностический файл нужно считать приватным до проверки на персональные сведения.

## Ограничения и безопасность

- Факт обнаружения GPU/runtime не означает, что ускорение или модель работают.
- GPU/SYCL, NPU, измеренный TPS, реальные модели и оборудование владельца не испытывались.
- Удалённые обновления каталога с Ed25519 и пользовательская поставка пока не реализованы.
- В A3.4 защищённая локальная история опирается на проверку реального Windows ACL и личный каталог данных, но не создаёт шифрованное хранилище. Приложения под учётной записью того же пользователя и локальный администратор остаются за пределами этой границы защиты.
- Не передавать диагностический JSON на сервер автоматически; не выводить неизвестное как 0 или оценку как измерение.
