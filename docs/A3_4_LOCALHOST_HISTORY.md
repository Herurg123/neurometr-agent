Разработка ограничена Agent, без merge/release/deploy.

## 1. Состав реализации

- `cmd/localui`: один Go-процесс Windows x64; определяет каталог установленного Agent, открывает случайный свободный TCP-порт только на `127.0.0.1`, пытается открыть системный браузер через штатный Win32 `ShellExecuteW`. В CI браузер отключается флагом `-no-browser`; секреты не выводятся.
- `internal/localui`: `net/http`, встраиваемые через `embed` HTML/JS/CSS без React/Node/CDN, заголовки безопасности, строго определённые маршруты, один одновременный диагностический запуск.
- `internal/history`: история в личном каталоге `os.UserCacheDir()/Neurometr/history` (на Windows `%LOCALAPPDATA%\Neurometr\history`). Имена строго из UUIDv4 `run_id`. Входные данные никогда не выбирают другие каталоги и пути.
- Генератор: **только существующий** `diagnostic.Generate(ctx, Options{ContractRoot: approvedRoot}, diagnostic.NativeProbes())`, без llmfit и облачных проверок. Сначала полный валидатор, потом атомарное сохранение. При чтении истории полный валидатор запускается заново.

## 2. HTTP-модель безопасности

- Listener `tcp4` исключительно `127.0.0.1:0`; фактический адрес проверяется программно. Только точный `Host=127.0.0.1:<выбранный порт>`: `localhost`, чужие домены, DNS rebinding и абсолютные URL отклоняются.
- `Origin` проверяется для всех запросов, а для `POST /api/run` обязателен точный `http://127.0.0.1:<порт>`; `Sec-Fetch-Site` (если представлен) допускает только `same-origin`/`none`. Никакого `Access-Control-Allow-Origin` или разрешающего preflight.
- При открытии `/` сервер выдаёт криптографически случайный 256-битный `neurometr_session` cookie (`HttpOnly`, `SameSite=Strict`, сессионный, без передачи в query). Отдельный 256-битный CSRF-токен доступен только после cookie-auth `GET /api/session`; мутации требуют строгий `X-Neurometr-CSRF` плюс cookie и Origin. Каждый перезапуск сервера выдаёт новые секреты.
- Запуск проверки **только** через `POST /api/run` с `application/json` и строго `{}`; данные запроса ограничены 1024 байтами, все неизвестные поля запрещены. Параллельная попытка во время диагностики получает 409; ограничен дедлайн запроса и независимые сроки native-проб. GET, OPTIONS и другие методы не могут запустить проверку.
- Строгий CSP (`default-src 'none'`, скрипты/стили/соединения только `'self'`, запрет iframe/object/form/base), `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Cross-Origin-Resource-Policy`, `Cross-Origin-Opener-Policy`, `Permissions-Policy`, `Cache-Control:no-store`. Нет удалённых assets, telemetrics, uploads или выполнения URL/команд из диагностического JSON.
- JS добавляет непроверенные системные строки **только через `textContent`**, без `innerHTML`, `eval`, динамического HTML, внешних скриптов или fetch сторонних адресов. JSON доступен в `<pre>` как текст, экспорт только ручным нажатием.
- История: `GET /api/history`, `GET /api/report/<uuid4>`, `GET /api/export/<uuid4>` требуют сессию. Для идентификаторов используется строгий формат UUIDv4, без свободных путей, `?query`, `..` и экспорта произвольных файлов. При просмотре и экспорте выполняется полная повторная проверка JSON. Контрактно неподдерживаемые версии и повреждённые файлы отвергаются.

## 3. Хранилище и права Windows

- Для каждого отдельного отчёта используется безопасный `run_id`, ограничение 2 МиБ, повторная `FullValidator.ValidateBytes`, запись `CreateTemp` → `Chmod(0600)` **как дополнительная мера, не доказательство Windows ACL** → `Sync` → закрытие → Win32 `MoveFileW` в том же каталоге **без замены существующего файла**. Гонка параллельных записей защищена mutex, уже существующий UUID не перезаписывается.
- Native Windows gate `GetNamedSecurityInfoW` и `GetAce` инспектирует реальные allow ACE DACL; разрешены только текущий SID, SYSTEM, Administrators, OWNER/CREATOR. NULL DACL, чужие allow ACE и недоступные ACL → отказ в открытии истории. `GetFileAttributesW` отвергает reparse point/junction как для личного app-каталога, так и самой истории. При ошибке приложение закрывается без выдачи приватных данных. CI дополнительно проводит независимый ACL-аудит через PowerShell, не печатая SID и пути.
- **Граница защиты:** от сторонних Windows-учётных записей при корректно настроенном ACL; локальный администратор, SYSTEM и вредоносное ПО с правами текущего пользователя по-прежнему могут получить доступ. Содержимое не шифруется. Это не доказательство абсолютной безопасности; реальное поведение ACL проверяется на hosted Windows и требует отдельной приёмки на компьютере владельца.
- При перечислении истории повреждённые записи пропускаются и учитываются в `invalid_count`; остальные продолжают работать. История не удаляется автоматически. Отображение ограничено 2000 валидными записями за вызов, без удаления старых.
- Сообщения об ошибках UI намеренно обобщены: никакие внутренние пути, hostnames, сырые логи, приватный JSON или токены не попадают в HTTP-ошибки и CI stdout.

## 4. Интерфейс

Русскоязычный офлайн HTML UI содержит кнопку «Проверить компьютер», статусы `ok/partial/failed/skipped`, сведения об ОС, CPU, RAM, DXGI GPU, непроверенную свободную VRAM и NPU, ошибки, ограничения, дату проверки, историю и раскрываемый полный JSON. Список формируется от нового к старому. Экспорт выдаёт тот же валидированный JSON с безопасным `Content-Disposition: attachment`; нет обязательной командной строки внутри браузера. Никаких TPS/fit/подтверждённого GPU backend не создаётся из наличия моделей в bundled-каталоге.

## 5. Проверки

- Ubuntu и Windows 2025 Go tests: Host, Origin, DNS rebinding, session cookie, CSRF, CORS, GET/OPTIONS, HTTP-лимит тела, параллельные запуски, XSS-сценарии, JSON validation, F01–F08, модельные негативные сценарии и все предыдущие pin-проверки.
- `internal/history` tests: создание и рестарт, повторная проверка точных байтов, отсутствие перезаписи, одновременно пишущие goroutine, повреждённый файл рядом с валидным, неверная версия, превышение 2 MiB, UUID/traversal и symlink.
- Windows hosted smoke запускает готовый, но **не публикуемый** CI-only бинарник, использует реальный Windows native-коллектор через HTTP, подтверждает `catalog_ref.origin=bundled`, Go FullValidator и read-only Python reference из Web `c0b9bc9d3a0e99e69dbde5f00f722b0225255b96`. Проверяет историю после перезапуска, отсутствие raw PII/токенов в логах и отказ в подключении через nonloopback интерфейс, если runner имеет таковой. При наличии Edge допускается короткий headless-проход без скриншотов, traces и video.
- В CI **не** публикуется сырой диагностический JSON, файл истории, cookie/CSRF или аппаратные данные Windows runner. Выводятся только коды прохождения, размеры и число обнаруженных адаптеров.

## 6. Известные ограничения и нерешённые вопросы

1. Без подписанного пользовательского ZIP нет end-user инсталлятора и автоматизированной проверки запуска со своего ПК. Используется source root/бинарник CI; публичный релиз запрещён.
2. HTTP loopback без TLS, защита cookie `SameSite=Strict`, Host/Origin/CSRF и браузерные политики не защищают от вредоносного процесса **того же пользователя** или локального администратора. Session cookie не имеет `Secure` при HTTP; секреты не выходят в URL или логи.
3. Win32 синхронные API могут не поддерживать физическое прерывание после deadline; Go pipeline имеет ограниченный срок возврата. На рабочем железе время может отличаться от CI.
4. `NPU` не опрашивается, свободная VRAM и реальная работа GPU runtime не измеряются. Cloud checks, llmfit system/fit и model benchmarks не запускаются. Не создавать оценок TPS из каталога.
5. Хранилище не зашифровано. Нет автоматического удаления, миграции между пользователями и синхронизации. Просмотр файлов с будущими неподдерживаемыми версиями заканчивается контролируемым отказом.
