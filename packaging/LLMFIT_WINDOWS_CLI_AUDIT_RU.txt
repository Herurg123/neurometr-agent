ПОДТВЕРЖДЕНО ПО ИСХОДНЫМ МАНИФЕСТАМ v1.1.20:
- Cargo workspace MIT; llmfit-tui (имя Cargo-пакета llmfit) MIT;
  llmfit-core MIT. Полный исходный текст MIT: LICENSES/llmfit-MIT.txt.
- Необходимая Rust-область для типовой CLI-сборки: llmfit-tui и
  llmfit-core, обычные dependencies и build-dependencies, target Windows MSVC,
  default features, без optional 'nats', без dev-dependencies.
- llmfit-tui/build.rs: встраивает собранные файлы llmfit-web/dist в бинарник;
  при отсутствии dist имеет fallback HTML/JS.

  в llmfit-web, затем cargo build --release --target ... и Windows signing.
  Поэтому npm-происхождение web UI надо рассматривать как потенциально
  ВСТРОЕННОЕ в подписанный EXE, хотя оно не лежит отдельными файлами ZIP.

  react@18.3.1, react-dom@18.3.1, scheduler@0.23.2,

НЕ УСТАНОВЛЕНО, ПУБЛИКАЦИЯ ОСТАЁТСЯ ЗАБЛОКИРОВАННОЙ:
- НЕ завершена независимая аттестация фактической компиляции подписанного EXE.
  Windows CI построил source-based Windows-target closure 215 package/version
  по normal/build edges, включая proc-macro и build-time crates; это кандидаты,
  а не доказанный состав машинного кода. Cargo.lock включает 659 записей
  всего workspace. Полный inventory: LLMFIT_WINDOWS_CLI_COMPONENTS_RU.txt.
- Полные лицензии, copyright и NOTICE каждого фактически нужного Rust crate
  частично включены через автоматическую привязку к Cargo.lock: полный набор
  имеющихся файлов лицензий/NOTICE хранится в
  LICENSES/rust-cli-source-license-texts.txt, с SHA исходного файла. Для
  crates без доступных стандартных notice файлов указано MISSING; такие
  обязательства пока нельзя объявить выполненными.
- Получена машинно проверяемая source-inventory на базе cargo metadata
  --locked --filter-platform x86_64-pc-windows-msvc и cargo tree для llmfit;
  не получен независимый SBOM именно официального подписанного EXE.
- Официальный Authenticode=Valid подтверждает подпись EXE, но не является
  аттестацией его точного Cargo graph, фактических features, содержимого
  встроенного dist или исходного commit. Без upstream build provenance
  реконструкция неизбежно имеет предел доказательности.
- npm CI/build-time инструменты не равны runtime bundle: чтобы установить
  точный состав встроенного JS, нужен отчёт upstream dist и лицензий его
  фактического bundle. Приведённые пять npm production packages — scope
  по lockfile, не доказательство точного JS asset content signed EXE.

Не выдавать указанный перечень за исчерпывающий SBOM. Этот файл специально
отделяет подтверждённые сведения от незакрытых лицензионных требований.

СБОРКА G4.2: Windows CI автоматически собирает полные исходные LICENSE/NOTICE
из закреплённого Cargo registry source cache в один документ с name/version,
SPDX, source URL и SHA256 каждого файла. Это НЕ замена лицензионному аудиту:
отсутствуют исходные LICENSE-like файлы для clipboard-win@5.4.1,
rmcp@3.5.1, rmcp-macros@3.5.1 и корневых llmfit/llmfit-core (для последних
основная MIT отдельно включена). Проверка copyright в неименованных файлах
и точной сборочной аттестации официального EXE остаётся открытой.

ПОЛНОТА APACHE 2.0: G4.2 заменяет ранее усечённую лицензию jsonschema
стандартным полным текстом Apache Software Foundation, с END OF TERMS и

ДОПОЛНИТЕЛЬНЫЕ ИСТОЧНИКИ ОТСУТСТВУЮЩИХ ТЕКСТОВ:
- clipboard-win@5.4.1 не содержал LICENSE в crate archive (Cargo include

  и перепроверен на точном upstream commit 5.4.1:
  3b27cf2bfd1adcfa6e0264eb51c1025ddaf0f342 (Cargo.toml version=5.4.1).
  Полный текст в комплекте побайтово совпадает с LICENSE на этом commit.
  Это подтверждает соответствие upstream версии 5.4.1, но сам исходный
  crates.io archive не содержал LICENSE из-за явного Cargo include.
- rmcp@3.5.1 / rmcp-macros@3.5.1 не содержали LICENSE-like файлов в crate
  archive, но корневой upstream LICENSE тега rmcp-v3.5.1 предоставлен
  отдельно: LICENSES/rmcp-3.5.1-upstream-LICENSE.txt.
  Annotated tag rmcp-v3.5.1 указывает на commit
  79437f291b2c44053d00dcd5db969fd0cca7c887; текст перепроверен
  на этом commit. Важно: в нём
  прямо указано, что не все прежние MIT-вклады перелицензированы на Apache.
  Следовательно, автоматическое отнесение всего crate только к Apache-2.0

Лицензии llmfit и llmfit-core покрывает upstream MIT, включённая отдельно.
Пять отсутствующих стандартных filenames в source audit — это наблюдение
Cargo crate archives; из них три дополнены upstream LICENSE, два MIT core.
Нельзя объявлять аудит официального EXE закрытым без evidence сопоставимости.
